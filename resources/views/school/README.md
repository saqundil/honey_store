# نظام جداول تقييم الطلاب

مشروع PHP Native لإدارة الطلاب وبناء قوالب تقييم ديناميكية وإدخال العلامات وطباعة تقارير A4. لا يستخدم Laravel أو أي JavaScript framework، ولا يحتاج إلى Node.js أو npm أثناء التشغيل.

## آخر التحديثات

تم تنفيذ التحديثات التالية بتاريخ 2026-08-29:

- إعادة بناء واجهة محرر القوالب على هيئة استوديو بثلاث لوحات: بنية القالب، المعاينة المباشرة، وخصائص العنصر المحدد.
- إعادة تصميم إنشاء التقرير كمسار واضح لإدخال البيانات، اختيار إصدار القالب، البحث عن الطلاب وتحديدهم، ثم الانتقال إلى إدخال العلامات.
- دعم فتح إنشاء التقرير من رابط قالب محدد عبر `?template=ID` مع اختيار الإصدار الحالي لذلك القالب، وحفظ آخر قالب مختار محليًا.
- تقييد التقرير الواحد بحد أقصى 32 طالبًا، مع البحث، التصفية حسب الصف، تحديد الكل وإلغاء التحديد.
- عرض رقم الطالب داخل التقرير كتسلسل صفوف يبدأ من 1 بدل عرض رقم الطالب المدرسي المخزن مثل `6A-001`.
- توحيد ترويسة العرض والطباعة: عنوان التقرير والصف يسارًا، شعار المدرسة في الوسط، والمادة والفصل والسنة يمينًا.
- تحسين خط الترويسة ومسافاتها وأحجامها، وتقليل المسافة بينها وبين الجدول إلى `4px` في الطباعة.
- ضبط ورقة الطباعة على A4 Portrait بارتفاع آمن `296mm` لمنع انقسام تقارير 32 طالبًا إلى صفحتين، مع إبقاء الإطار المزدوج ثابتًا قرب أسفل الصفحة.
- تمييز جميع أعمدة `calculated_total` بخلفية رمادية خفيفة `#ededed` في الرأس والخلايا.
- تفعيل المحافظة على الألوان والخلفيات عند الطباعة باستخدام `print-color-adjust: exact`.
- إضافة تغطية اختبارية للترقيم التسلسلي وفئات أعمدة المجموع.
- إضافة دوري `super_admin` و`teacher` مع Authorization مركزي وعزل موارد المعلمين.
- إضافة السنوات المملوكة للمعلم، الفصول الأكاديمية، المراحل، الصفوف السياقية، وسجل `class_enrollments` التاريخي.
- إضافة Teacher Setup Wizard متعدد الخطوات، مع تحويل المعلم الجديد إليه تلقائيًا حتى يكتمل إعداده.
- إضافة Migration Runner غير تدميري وتغطية اختبارية لعزل المعلمين ورفض العلاقات العابرة للملكية.
- إضافة سجل علامات ديناميكي لتعيين مخططات التقييم للصفوف، والحفظ التلقائي، والقفل وإعادة الفتح، وسجل تدقيق لكل تغيير.
- إضافة تقارير سجل العلامات للصف والفصل والطالب والاختبار، مع طباعة A4 طولية أو عرضية وورقة مستقلة لكل قالب اختبار.
- إضافة Revision Tokens لكل خلية لمنع الكتابة المتزامنة القديمة، مع استجابة `409 Conflict` وتحديث تلقائي للـRevision بعد كل حفظ.
- جعل دفعات الحفظ وتغييرات الحالة ذرية باستخدام Transactions وSavepoints وقفل سجل الاختبار، وتثبيت تاريخ النشر وسجل التدقيق كبيانات غير قابلة للتعديل أو الحذف على مستوى MySQL.
- إضافة مستورد قوالب من ملف Word متعدد الجداول، أو جدول ملصوق من Word أو Excel، أو ملف PDF نصي.
- تنظيم كل قالب داخل مجموعة إلزامية مملوكة للمعلم، مع تجميع القوالب القديمة تلقائيًا تحت «قوالب عامة».
- قراءة دمج خلايا الرؤوس عند اللصق وتحويلها إلى مجموعات رؤوس متداخلة، واستنتاج الأعمدة من مواضع النص عند استخدام PDF.
- تخمين أنواع الأعمدة والعلامات القصوى ومصادر الأعمدة المحسوبة من نص الرؤوس، مع ملاحظات مرئية بكل ما جرى تخمينه أو إضافته.
- قراءة صف المجموعات كصف رؤوس بحساب الأعمدة التي يغطيها لا عدد خلاياه، فلا يسقط صف الرؤوس الحقيقي في الجداول ذات الخلايا المدمجة العريضة.
- قراءة الرقم في نهاية الرأس كعلامة قصوى عندما يتبع هذا العرف نصف أعمدة العلامات، واشتقاق علامة عمود المجموع من مجموع مصادره.
- نقل دوران نص الرأس من Word أو Excel إلى `display_direction`، وقراءة عرض كل عمود من المصدر واستخدامه كنسبة من عرض الجدول.
- فصل مظهر ورقة التقرير وجدولها في `assets/css/report-sheet.css` المشترك، فصارت معاينة المحرر ومعاينة القالب تعرضان ورقة الطباعة نفسها بأنماطها وترويستها وقياس A4 وإطارها المزدوج.
- إضافة قاسم اختياري للعمود المحسوب (`table_formulas.divisor`) عبر migration، ليدعم رؤوسًا مثل «المجموع 8/2» أي مجموع المكوّنات مقسومًا على 2.

## المتطلبات

- PHP 8.1 أو أحدث مع `PDO`, `pdo_mysql`, `mbstring`, `session`, `dom` و`zip` لرفع ملفات DOCX.
- MySQL 5.7.8+ أو MySQL 8، أو MariaDB حديث يدعم نوع `JSON`.
- Apache عبر XAMPP أو WAMP أو Laragon، أو Apache/PHP/MySQL مستقل.
- تفعيل `mod_rewrite` و`AllowOverride All` عند استخدام Apache لتطبيق حماية `.htaccess`.
- `pdftotext` من poppler أو Xpdf، اختياريًا، لاستيراد القوالب من ملفات PDF. اللصق من Word أو Excel لا يحتاجها.

## التثبيت

1. ضع المجلد داخل `htdocs` في XAMPP، أو `www` في WAMP/Laragon.
2. أنشئ الجداول باستيراد `database/schema.sql` عبر phpMyAdmin، أو:

```bash
mysql -u root -p < database/schema.sql
```

3. اضبط الاتصال من متغيرات البيئة التالية، أو عدّل القيم الافتراضية في `config/database.php`:

```text
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=student_assessment
DB_USER=root
DB_PASS=
APP_URL=http://localhost/hiyam
APP_TIMEZONE=Asia/Amman
SEED_ADMIN_PASSWORD=ضع-كلمة-مرور-مؤقتة-قوية
PDFTOTEXT_PATH=C:\poppler\bin\pdftotext.exe
```

4. شغّل البذرة من سطر الأوامر:

```bash
php database/seed.php
```

لترقية قاعدة موجودة بدل إعادة إنشائها، شغّل migrations بالترتيب المسجل:

```bash
php database/migrate.php
```

يحفظ Runner الملفات المنفذة في `schema_migrations` ويتجاوزها بأمان عند التشغيل المتكرر. لا تستورد `schema.sql` فوق قاعدة تحتوي بيانات.

5. افتح `http://localhost/hiyam`. الحساب الافتراضي هو `admin@example.com`، وكلمة المرور هي قيمة `SEED_ADMIN_PASSWORD`. عند غيابها تكون مؤقتًا `ChangeMe!2026` ويجبر النظام المدير على تغييرها أول مرة.

للتجربة بخادم PHP الداخلي، بعد تشغيل MySQL وتهيئة القاعدة:

```bash
set APP_URL=http://127.0.0.1:8080
php -S 127.0.0.1:8080
```

> خادم PHP الداخلي لا يطبق `.htaccess`؛ استخدم Apache في الإنتاج، واجعل الحماية على مستوى إعداد VirtualHost أيضًا.

## بنية المشروع

```text
admin/       صفحات لوحة التحكم والقوالب والطلاب والتقارير
api/         نقاط AJAX المحمية بالجلسة وCSRF
assets/      CSS وJavaScript والخطوط والشعار المحلية، ومنها report-sheet.css المشترك بين المعاينة والطباعة
config/      إعداد التطبيق واتصال PDO
database/    مخطط MySQL والبذرة
includes/    Bootstrap والمصادقة والتخطيط والترويسة الثابتة
reports/     واجهة الطباعة المستقلة
src/         Services وRepositories
tests/       اختبارات المنطق التي لا تحتاج قاعدة بيانات
```

## قاعدة البيانات

يدير `database/schema.sql` الجداول التالية:

- `admin_users`, `academic_years`, `academic_terms`, `stages`, `classes`, `subjects`, `students`, `class_enrollments`.
- `table_templates` و`table_template_versions` لحماية التقارير القديمة من تعديلات القالب.
- `table_header_groups` كشجرة ذاتية بواسطة `parent_id`.
- `table_columns`, `table_formulas`, `table_formula_items` لتعريف الأعمدة واعتماداتها.
- `assessment_schemes`, `assessment_scheme_versions`, `assessments`, `assessment_templates` لتعريف الاختبارات ذات الإصدارات الثابتة.
- `class_scheme_assignments`, `class_assessments`, `grade_values`, `grade_value_audits` لتعيين المخطط وإدخال العلامات وتدقيقها.
- `reports`, `report_students`, `report_values` لحفظ التقرير ونسخة أسماء طلابه وقيمه.

لا تُخزن قاعدة البيانات HTML. كل جدول يُبنى وقت العرض من Configuration. يرتبط التقرير بـ`template_version_id` ثابت، ولذلك لا يتغير تقرير قديم عند إنشاء إصدار قالب جديد.

السنوات والفصول والمراحل والصفوف والطلاب مملوكة للمعلم. يحتفظ `students.class_id` بالصف الحالي للتوافق مع التقارير القديمة، بينما يمثل `class_enrollments` مصدر الحقيقة التاريخي لعضوية الطالب عبر الفصول. تفرض Foreign Keys المركبة تطابق المعلم بين الطالب والصف والفصل.

## الأدوار وإعداد المعلم

يدعم `admin_users.role` دورين:

- `super_admin`: إدارة النظام والوصول الإداري الصريح إلى البيانات القديمة.
- `teacher`: بيانات معزولة بحسب `teacher_id` ولا يرى موارد معلم آخر.

عند أول دخول للمعلم، يتحقق النظام من وجود عام دراسي وفصل ومرحلة وصف. إذا كان الإعداد ناقصًا يحوله إلى `admin/setup.php` لإكمال الخطوات، بدل عرض لوحة تحكم فارغة. حالة الإعداد مشتقة من البيانات ولا تحتاج جدولًا مستقلًا.

توجد الحماية المركزية في `AuthorizationService`. تستقبل Repositories الخاصة بالقوالب والتقارير Actor ID صريحًا، وتُرفض IDs غير المملوكة Server-side حتى عند تعديل URL أو Request يدويًا.

## إنشاء قالب

كل قالب ينتمي إلى مجموعة، ولا تسمح قاعدة البيانات بحفظ قالب منفرد. تظهر القوالب في القائمة تحت عناوين مجموعاتها. عند إنشاء قالب أو استيراده اختر مجموعة موجودة، أو اكتب اسمًا جديدًا ليُنشئها النظام تلقائيًا. تُنقل القوالب السابقة عند الترقية إلى مجموعة «قوالب عامة» خاصة بمالكها.

1. افتح **قوالب الجداول** ثم **قالب جديد**، واختر مجموعة القوالب أو اكتب اسم مجموعة جديدة. لبناء أسرع من جدول موجود، استخدم **استيراد Word أو جدول** بدلًا عنه، ثم تابع من الخطوة 3.
2. استخدم لوحة **بنية القالب** لإضافة مجموعات الرؤوس والأعمدة وترتيبها بالسحب.
3. حدّد أي عنصر وعدّل خصائصه من لوحة الخصائص، مثل الاسم والنوع والمفتاح والعلامة القصوى والعرض والاتجاه.
4. راقب النتيجة فورًا في لوحة المعاينة المباشرة.
5. يمكن اختيار مجموعة أب لبناء رؤوس متعددة المستويات.
6. اضغط **حفظ إصدار جديد**. تعديل قالب محفوظ لا يمس الإصدار السابق.

يجب أن يحتوي كل قالب على عمود واحد من نوع رقم الطالب وعمود واحد من نوع اسم الطالب. `HeaderLayoutCalculator` يحسب `rowspan` و`colspan` تلقائيًا ولا تُخزن هذه القيم.

ملفات الواجهة الأساسية هي `admin/templates/edit.php` و`assets/js/table-builder.js` و`assets/css/template-builder.css`.

## استيراد قالب جاهز

بدل بناء الأعمدة يدويًا، افتح **قوالب الجداول** ثم **استيراد Word أو جدول** (`admin/templates/import.php`).

**رفع ملف Word متعدد الجداول** يدعم صيغة DOCX حتى 12MB و100 جدول. يختار المستخدم مجموعة واحدة للملف، ثم يُنشأ داخلها قالب مستقل مباشرة من كل جدول. يُستخدم النص السابق للجدول اسمًا له تلقائيًا، أو اسم الملف مع رقم الجدول عند غياب العنوان. تعرض الصفحة بعد المعالجة روابط القوالب الناجحة وأسباب فشل أي جدول منفرد. يجب مراجعة القوالب المنشأة قبل استخدامها لأن أنواع الأعمدة والعلامات والمعادلات تظل مستنتجة من الرؤوس. ملفات DOC القديمة تحتاج إلى الحفظ بصيغة DOCX أولًا.

أما اللصق وPDF فيقرآن رأس جدول واحد ويبنيان مسودة تُفتح في المحرر، ولا يُحفظ أي إصدار قبل الضغط على **حفظ الإصدار**.

**اللصق من Word أو Excel** هو المسار الأدق. انسخ الجدول نفسه لا صورة عنه، والصقه في المساحة المخصصة. تصل معه خاصية `colspan` لخلايا الرأس، فتتحول مباشرة إلى `table_header_groups` متداخلة، وتصبح الخلايا التي تحتها أعمدة تلك المجموعة. اللصق النصي المفصول بـTab أو بمسافتين فأكثر مدعوم أيضًا، لكنه بلا مجموعات رؤوس. النص المجرد لا يحمل الدمج، فصف الرؤوس الممتد يصل ناقص الأعمدة، والرأس الملتف على سطرين يصل صفًا زائدًا. لذلك يُرفض النص الذي تختلف فيه أعمدة صفوف الرأس برسالة تطلب لصق الجدول نفسه، بدل بناء جدول خاطئ بصمت.

**رفع PDF** مسار احتياطي أقل دقة. الـPDF لا يخزن جدولًا بل نصًا بإحداثيات، فيمرّ الملف على `pdftotext -layout` وتُستنتج حدود الأعمدة من الأشرطة الفارغة في صفوف البيانات، ويصبح الرأس الذي يغطي أكثر من شريط خلية ممتدة. يحدد الحقل رقم الصفحة، ويصحح خيار الاتجاه ترتيب الأعمدة إن جاء معكوسًا. الملف الممسوح ضوئيًا كصورة غير مدعوم لأنه لا يحمل نصًا.

يُقرأ من اللصق أيضًا شكل الرأس لا نصه فقط. الرأس المدوّر في Word أو Excel يصل كـ`display_direction: vertical` فيُعرض عموديًا كما في المصدر، وعرض كل عمود يُقرأ من `width` أو `style` الخاص بخلاياه. العروض تُستخدم نسبيًا لا كقياس مطلق، لذلك لا تُعتمد إلا إذا أعلن المصدر عرضًا لكل عمود، وإلا رجع الجميع إلى الافتراضيات حتى لا تختل النسب. العمود ذو الرأس العمودي بلا عرض معلن يأخذ عرضًا ضيقًا، لأن التدوير غرضه تضييق العمود.

أيًا كان المصدر، لا يحمل الجدول أنواع الأعمدة ولا العلامات القصوى ولا المعادلات، فتُخمَّن من نص الرؤوس:

| ما يظهر في الرأس | ما يُستنتج |
| --- | --- |
| `الرقم`، `م`، `التسلسل` | `student_number` |
| `اسم الطالب`، `الاسم` | `student_name` |
| `المجموع`، `الكلي`، `النهائي` | `calculated_total` بمعادلة `SUM` |
| `المعدل`، `المتوسط` | `calculated_average` |
| `النسبة`، `المئوية` | `percentage` مع قاعدة تساوي مجموع العلامات القصوى للمصادر |
| `التاريخ` | `date` |
| `ملاحظات`، `التقدير` | `text` |
| غير ذلك | `manual_mark` |

تؤخذ العلامة القصوى من رقم بين قوسين مثل `الواجب (10)`، أو بعد `من` أو `/`، أو من صف الأرقام المجرد الذي يلي الرؤوس، أو من رقم في نهاية الرأس مثل `سلامة اللغة 2` وهو العرف الشائع في الكشوف العربية. لأن `اختبار 2` قد يكون اسمًا لا علامة، لا يُعتمد الرقم في النهاية إلا إذا اتبعه نصف أعمدة العلامات على الأقل، وعندها يُزال من اسم العمود. علامة عمود المجموع تُشتق من مجموع العلامات القصوى لمصادره متى عُرفت كلها، فهي أوثق من رقم غامض في نص مثل `المجموع 8/2`.

مصادر العمود المحسوب هي أعمدة العلامات في مجموعة الرأس نفسها، وإلا سلسلة أعمدة العلامات التي تسبقه مباشرة. العمود الذي يبدو محسوبًا ولا مصادر له يُحوَّل إلى علامة يدوية حتى تبقى المسودة قابلة للحفظ. تُضاف أعمدة الهوية الناقصة تلقائيًا في البداية. كل ما جرى تخمينه أو إضافته يظهر في شريط ملاحظات أعلى المحرر.

المنطق في `src/Services/TableImportService.php` ولا يعتمد على قاعدة البيانات، واستخراج PDF في `src/Services/PdfTableExtractor.php`. الـPDF لا يحمل دورانًا ولا عروضًا يمكن قراءتها، فأعمدته تأخذ الافتراضيات دائمًا.

## معاينة القالب

معاينة المحرر (`admin/templates/edit.php`) ومعاينة القالب (`admin/templates/preview.php`) تعرضان ورقة الطباعة نفسها: ملف `assets/css/report-sheet.css` المشترك، وترويسة `includes/report-header.php` نفسها ببيانات نموذجية، وصنف `report-sheet--dense` نفسه. لذلك ما يظهر في المعاينة هو ما يخرج من الطابعة، بما فيه إطار الورقة المزدوج وقياسات A4 والرأس العمودي وتظليل أعمدة المجموع.

يبني `TableRenderer` جدول الطباعة في PHP، بينما تبنيه `assets/js/table-builder.js` في المتصفح لتبقى المعاينة فورية أثناء التحرير. الاثنان يُخرجان الترميز نفسه حرفيًا: الأصناف و`colspan` و`rowspan` و`header-label` و`header-mark` و`cell-value`. يحرس `tests/preview_parity_test.php` هذا التطابق بتشغيل مُصيّر المتصفح في Node ومقارنة ناتجه بناتج `TableRenderer` حرفًا بحرف.

يحمل `report-sheet.css` مظهر الورقة والجدول فقط بلا أي قاعدة على مستوى الصفحة، فيصلح للتحميل داخل لوحة التحكم. أما `report.css` فيحمل تخطيط صفحة الطباعة المستقلة وحدها.

## المعادلات

اختر نوع عمود محسوب، ثم العملية `SUM` أو `AVERAGE` أو `PERCENTAGE` وحدد الأعمدة المصدر. تحفظ الاعتمادات بواسطة Column IDs ومفاتيح ثابتة مثل:

```text
SUM(month_1_ideas,month_1_links,month_1_language,month_1_style)
SUM(month_1_total,month_2_total)
```

لا تستخدم الحسابات أرقام الخلايا أو ترتيبها. يمنع `FormulaEngine` المراجع المفقودة والاعتماد على الذات والدورات. يحسب JavaScript النتيجة فوريًا، ثم يعيد PHP الحساب قبل حفظها ولا يثق بنتيجة المتصفح.

### القاسم

يقبل كل عمود محسوب قاسمًا اختياريًا في حقل **مقسوم على**، فيصبح الناتج `العملية(المصادر) ÷ القاسم`. هذا يغطي العرف الشائع في رؤوس مثل `المجموع 8/2`: المكوّنات تجمع 8 ثم تُقسم على 2 فتكون العلامة القصوى 4. القيمة الافتراضية 1 فلا يتغير أي قالب قائم، وتمنع `chk_formula_divisor` القيم غير الموجبة على مستوى MySQL.

يُخزَّن القاسم في `table_formulas.divisor`، ويظهر في `expression` المحفوظ بصيغة `(SUM(a,b,c))/2` للتوثيق. يطبّقه `FormulaEngine` قبل التقريب، وتطبّقه معاينة المحرر بالطريقة نفسها.

يقرأ المستورد `8/2` في رأس عمود محسوب فيضبط القاسم 2 والعلامة القصوى 4، ويسجّل ذلك في ملاحظات المسودة. لا يُقرأ الشكل قسمةً إلا إذا كان الرقم الثاني أصغر من الأول ومطابقًا لمجموع علامات المصادر، فلا يُخلط بـ`من 8`.

## سجل العلامات والحفظ التلقائي

من صفحة **سجل العلامات** يعيّن المعلم الإصدار الحالي من مخطط منشور إلى صف من الفصل الدراسي نفسه. ينشئ النظام `class_assessments` ديناميكيًا لكل اختبار نشط، ولا يعتمد على عدد ثابت للاختبارات أو القوالب.

تعرض صفحة إدخال الاختبار كل Template Assignment في تبويب مستقل باستخدام `TableRenderer`. تأتي قائمة الطلاب من `class_enrollments` التاريخية، وتحفظ كل خلية وفق الاختبار والقالب والـEnrollment والعمود. يعيد الخادم التحقق من المجال وخطوة العلامة، ويحسب الأعمدة المشتقة بواسطة `FormulaEngine` قبل الحفظ.

يبدأ الحفظ التلقائي بعد توقف قصير عن الإدخال ويعرض حالة الحفظ. أول حفظ ينقل الاختبار من `draft` إلى `open`. عند القفل تصبح الجداول للقراءة فقط ويرفض الخادم أي تعديل، ويمكن للمعلم إعادة فتح الاختبار. يسجل `grade_value_audits` إنشاء القيم وتعديلها وعمليات الفتح والقفل وإعادة الفتح، ولا ينشئ الحفظ المتكرر Audit جديدًا إذا لم تتغير القيمة.

ترسل الواجهة Revision متوقعًا لكل خلية. إذا تغيّرت الخلية من جلسة أخرى، يرفض الخادم الدفعة كاملة بـ`409 Conflict` بدل الكتابة فوق القيمة الأحدث. الحفظ متعدد الصفوف ذري حتى عند استدعاء الخدمة داخل Transaction خارجية، وتُسلسل عمليات الحفظ والقفل بواسطة `SELECT ... FOR UPDATE` على الاختبار.

إصدارات مخططات التقييم المنشورة وتعريفات الاختبارات وتعيينات قوالبها وسجلات `grade_value_audits` تاريخ ثابت Append-only. تمنع Triggers في MySQL أوامر `UPDATE` و`DELETE` المباشرة لهذه السجلات، وليس عبر واجهة التطبيق فقط. لإنشاء تعديل وظيفي يُنشر إصدار مخطط جديد، ولا يُعاد كتابة الإصدار السابق.

## تقارير سجل العلامات

يفتح رابط **التقارير والكشوف** من بطاقة الصف صفحة ملخص للفصل الدراسي. تتولد أعمدة الملخص من Assessments الموجودة في إصدار المخطط، وتعرض علامة كل اختبار والمجموع والنسبة لكل طالب. إذا كان للاختبار `weight` صريح، يستخدم الوزن في المجموع العام مع إبقاء علامة الاختبار على مقياسها الأصلي؛ وإلا تستخدم العلامة القصوى للاختبار.

يحتسب الملخص قوالب الاختبار المطلوبة والنشطة فقط حتى لا يخفض قالب اختياري فارغ نسبة الطالب. تبقى القوالب الاختيارية متاحة في تقرير الاختبار التفصيلي. لا تدخل الأعمدة المحسوبة مرة أخرى في التجميع؛ يعتمد الملخص أعمدة `manual_mark` ثم يترك `FormulaEngine` لعرض الحسابات داخل كل قالب، وبذلك لا يتكرر المجموع.

تتوفر ثلاثة أنواع من الطباعة:

- كشف الصف والفصل: الطلاب في الصفوف والاختبارات في الأعمدة مع الإجمالي والنسبة.
- كشف الطالب: درجات طالب واحد عبر اختبارات المخطط وحالة كل اختبار.
- تقرير الاختبار: ورقة مستقلة لكل Template Assignment، بنفس ترويسة المدرسة و`TableRenderer` المستخدمين في بقية النظام.

يمكن اختيار A4 Portrait أو Landscape من الواجهة أو تغيير الاتجاه داخل صفحة الطباعة. ملفات Phase 6 الأساسية هي:

- `admin/gradebook/report.php`

## إنشاء تقرير وإدخال العلامات

1. افتح **التقارير** ثم **تقرير جديد**، أو افتح الصفحة من قالب محدد باستخدام `admin/reports/create.php?template=ID`.

تُخفى صفوف الطلاب غير المطابقة للصف أو البحث بصورة فعلية، ولا تدخل ضمن التحديد. ملفات الواجهة الأساسية هي `admin/reports/create.php` و`assets/js/report-create.js` و`assets/css/report-create.css`.

## الطباعة

زر **طباعة** يفتح واجهة مستقلة تستخدم نفس `TableRenderer`. التصميم RTL وبحجم A4 Portrait، مع ترويسة مشتركة وإطار مزدوج. الشعار والخطوط محفوظة داخل `assets` ولا تحتاج الطباعة إلى الإنترنت.

قواعد الطباعة الحالية:

## الأمان

- PDO Prepared Statements وتعطيل Emulated Prepares.
